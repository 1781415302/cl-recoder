1. **计划任务执行时限仍为72小时。** 若这次任务持续运行且配置未变，预计10月4日15:39左右达到时限，可能被任务调度器停止。应取消常驻任务运行时限，并在安装/更新脚本中明确写入，避免重建任务后恢复默认值。

## 优化和诊断能力优先级

1. 先修常驻任务的时限与电池策略，保持用户身份、登录触发、最高权限及单实例合同。
2. 补有容量上限的本地诊断日志与状态错误分类：启动/退出、数据库错误、管道超时/拒绝访问。当前只显示“未运行”的失败合并会降低下次排查效率；本轮没有发生这类探测失败。
3. 在明确可见/隐藏状态后做GUI对照采样；源码仍配置后台0.5秒轮询，优先验证隐藏时暂停重统计查询的收益，再分析图表重绘。无需先改统计引擎或数据库schema。
4. 查询设备kind改为主键查询可作为小幅维护优化；避免在缺少更大真实数据基准时上缓存表、重写存储或加入新性能框架。
